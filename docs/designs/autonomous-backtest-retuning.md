## Problem Statement

AlphaCa's live strategy parameters (delta ranges, exit thresholds, expiry
window) are reasonable defaults, never empirically validated. P&L plays a
crucial role in hackathon judging. The strategy has fired zero real signals
across every day observed live so far, so there's real risk the untested
defaults won't produce meaningful, profitable activity during the single-week
judging window.

## What Makes This Cool

The agent doesn't just trade a static rule set. Every day it re-evaluates its
own parameters against an expanding historical backtest, autonomously (no
human approval step) tightens them when the evidence clearly supports a
change, and narrates via Hermes what it found and why. Judges see a system
that visibly gets sharper over the demo week, backed by real statistical
evidence rather than static rules or vibes.

## Constraints

- Build week starts 2026-08-28, two days out.
- No historical options chain/Greeks data available from Alpaca. Options
  pricing must be approximated via Black-Scholes fed by real historical
  underlying prices.
- Real live trade frequency observed as very low (zero signals across every
  live day tested so far). Re-tuning cannot depend on a live-trade-count
  trigger, or it may never fire during the whole judging week.
- Autonomous changes are scoped to delta ranges, exit thresholds, and expiry
  window only. Position-size risk % and watchlist membership are out of
  reach for the autonomous loop.
- Re-tune decisions must clear a real statistical significance bar, not just
  "the new backtested number is bigger."
- The LLM (Hermes) only narrates a decision already made deterministically.
  It never makes the tuning decision itself.

## Premises

- P1: An autonomous, backtest-grounded re-tune loop with LLM narration
  strengthens all three judged criteria (autonomy, testable thesis, P&L) at
  once, not one at the expense of another.
- P2: Current parameters were never empirically validated, and real trading
  activity has been sparse in live testing. Validating before/during the
  judging week is a real need, confirmed by our own observation, not a
  hypothetical one.
- P3: Tunable parameters need to move out of `config/watchlist.py`'s Python
  constants into a separate mutable parameters file that both the live
  strategy and the autonomous re-tuner read/write at runtime. An autonomous
  process should not rewrite live `.py` source on disk.

## Approaches Considered

### Approach A: Minimal viable
Backtester reusing existing modules directly. Re-tune loop swaps a parameter
in whenever the new backtested number is better than the current one. No LLM
narration. Fewest new files, fastest to ship. Rejected: swaps on noise with
this few real trades, and weakest on the demo's "whoa" factor.

### Approach B: Full pipeline from day one
Backtester + re-tune loop + Hermes LLM as the actual decision-maker, built
together from the start. Most impressive if flawless. Rejected: the LLM
directly deciding live risk-parameter changes with no gate is the riskiest
possible design — an incoherent or wrong decision on judging day, with nobody
reviewing it first, actively hurts the "clear testable thesis" story instead
of helping it.

### Approach C: Threshold-gated hybrid
Backtester + a re-tune loop gated by a real statistical significance check
(not just "the number went up") + Hermes narrating the decision after it's
already been made deterministically.

## Recommended Approach

Approach C. It reuses the same core pieces as A and B, avoids re-tuning on
noise (unlike A), and keeps the LLM's job bounded to narrating a clean
decision object instead of making the call itself (unlike B) — which is both
the more defensible design for a technically sophisticated judge and, not
coincidentally, the easier one to safely wire Hermes into.

## Open Questions

- Exact significance-test methodology for the threshold gate (minimum sample
  size, confidence threshold) — decide during backtester build.
- Exact schema for the mutable parameters file.
- Exact Hermes integration mechanism for the narration step (custom tool vs.
  a simpler prompt reading a structured log) — deferred until the backtester
  and re-tune loop are solid.

## Success Criteria

- Backtester produces a real historical P&L estimate for the exact debit
  spread structure traded live, using real historical stock prices plus
  Black-Scholes with conservative assumptions (trailing realized volatility,
  no lookahead, a slippage haircut on entry/exit pricing).
- Backtester reuses `signals.py`, `options_selector.py`'s
  `select_debit_spread`, `execution.py`'s `size_position`, and
  `position_manager.py`'s `evaluate_exit` unchanged — same logic as live,
  not a parallel reimplementation.
- Daily autonomous re-tune job runs with no human approval step, driven by
  the expanding backtest dataset, not a live-trade-count trigger.
- A parameter only gets swapped when its backtested edge clears a real
  statistical significance bar.
- Re-tuner never touches watchlist membership or position-size risk %.
- Every re-tune decision (swap or no-swap) is logged with full reasoning to
  the existing journal, matching the audit-trail style already used for live
  trades.
